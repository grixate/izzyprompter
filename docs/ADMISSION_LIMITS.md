# IZZY — session admission and resource budgets

Status: 2026-10-09, Slice 5.3. Implemented locally; not a public deployment or a complete denial-of-service defence.

## Defaults

These are conservative **per-instance** starting budgets, not measured hosting capacity. Use one Phoenix instance; sessions are not replicated.

| Budget | Public release | Trusted-LAN release | Development |
| --- | --- | --- | --- |
| Retained session processes | 32 | 16 | 64 |
| Admitted creation attempts per peer / minute | 10 | 30 | 60 |
| Admitted creation attempts total / minute | 60 | 120 | 120 |
| Raw HTTP JSON body | 3 MiB | 3 MiB | 3 MiB |
| Decoded script text | 2 MiB | 2 MiB | 2 MiB |
| Normalized paragraphs | 5,000 | 5,000 | 5,000 |

The test environment uses separate, larger defaults. Low-budget unit tests use isolated gate/supervisor processes; the real public release smoke test explicitly uses two sessions, four per-peer attempts, and ten total attempts.

`POST /api/sessions` is admitted **before JSON parsing**. Invalid protocol, oversized body, invalid script, and capacity failures consume an admitted attempt too. Requests refused by the gate do not consume another peer's remaining global quota. Health, static pages, reconnects, channel commands, and live edits do not spend creation quota. Origins are checked first; this is not authentication for non-browser traffic.

The gate uses a fixed 60-second window, reset lazily on the next request, with at most 2,048 peer keys. It refuses new keys rather than evicting live quotas. A process restart resets these in-memory counters; bursts can straddle a window boundary. Keys are ephemeral salted HMACs of the socket/proxy-resolved address, not raw IP addresses, account identities, or product analytics. They are replaced on the next window reset and are not intentionally logged or persisted.

Session capacity is enforced atomically by the supervisor, including simultaneous requests. Existing sessions are **not evicted** to admit a new one. Closing a browser does not immediately free its session: ephemeral sessions retain their script until six hours of inactivity, termination, or server restart. A stopped session releases its slot. Restarting is not a routine recovery action because it ends all active sessions.

Only JSON request bodies are supported. Unsupported media types return 415; oversized raw JSON returns 413, including an adapter read that overshoots its requested chunk length. Each body read has a five-second timeout. The decoded script must also be valid, nonempty normalized UTF-8 text within the byte and paragraph budgets. Escaping/JSON overhead can exceed the raw-body budget even for a script within its decoded budget. Whole-script replacements obey the same text/paragraph limits; Quick Edit retains the existing paragraph identities and permits temporary empty text within its existing 2 MiB patch/full-script budget.

## Responses and recovery

- 429 `rate_limited`: `Retry-After` seconds and `Cache-Control: no-store`. The entry page preserves/persists the draft and temporarily disables Start, showing a countdown. It never automatically creates a session when the countdown finishes.
- 503 `session_capacity`: non-cacheable, with a 30-second retry suggestion. The page explains that the server is full, preserves the draft, and leaves retry explicit. The suggestion is not a promise that a slot will open in 30 seconds.
- 503 `session_unavailable`: the gate fails closed if unavailable; the page retains the existing connection/retry guidance.
- 413: reduce the script size. Status-based guidance also handles an HTML response generated by a proxy.
- 422 `invalid_session`: invalid content/speed, including script byte/paragraph limits. No session is created.

`Retry-After` is exposed to allowed cross-origin clients for split-port development. Existing sessions continue operating when new creation reaches its quota/capacity. Their separate 64-connection and 1,024 logical-command-identity budgets remain unchanged.

## Runtime configuration

Set these before starting a release; malformed/out-of-range values fail startup instead of disabling protection:

| Variable | Accepted range |
| --- | --- |
| `IZZY_MAX_SESSIONS` | 1–1,024 |
| `IZZY_CREATE_PER_IP` | 1–1,000 per minute |
| `IZZY_CREATE_TOTAL` | 1–10,000 per minute |
| `IZZY_TRUSTED_PROXY_IPS` | Optional comma-separated list of up to 32 exact IPv4/IPv6 addresses; public profile only |

Defaults use the actual socket peer and ignore `X-Forwarded-For`. This prevents a direct client from changing its bucket by forging a header. Shared NAT addresses share a budget.

Behind a public reverse proxy, configure **only exact trusted immediate/intermediate proxy addresses**, keep the Phoenix listener inaccessible to direct public traffic, and configure the proxy to overwrite forwarding headers or append the real connecting address correctly. The resolver walks a valid chain from right to left and chooses the first untrusted hop. Malformed/oversized/multiple forwarding headers fall back to the socket peer. DNS names, wildcards, and CIDRs are not accepted. Without correct proxy trust, all clients behind that proxy share its bucket. Trusted-LAN mode ignores proxy-trust configuration and always uses the direct peer.

## Still required before public beta

Choose and test the actual TLS/proxy/hosting topology, including edge request/body/connection/handshake timeouts and rate limits. Slice 5.4 adds initial frame/channel/session message guards and local aggregate diagnostics; see `REALTIME_GUARDS.md`. Measured memory/CPU budgets, fairer anonymous admission, external content-redacted monitoring/alerts, deployment/rollback acceptance, and physical browser/device checks remain open (physical testing is deferred, not passed). These application-level budgets cannot stop network floods or eliminate retained-session exhaustion by a determined attacker.
