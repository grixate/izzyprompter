# IZZY main page and PRO — art direction and quality contract

14 October 2026. The owner explicitly requires extraordinary design quality for both pages. This brief makes that requirement actionable within the [execution plan](UX_PRO_EXECUTION_PLAN.md). It does not approve a final layout or authorize publication.

## The intended impression

**A finely made instrument that happens to live in a browser.** The wheel is the recognizable object; the page gives it scale, credible material, breathing room and useful movement. Every visual decision should increase understanding or desire. Technical implementation details belong outside the main product story.

Main page: immediate clarity and confidence, with the user's script and the two-screen relationship available straight away. PRO: desire and ownership, with skins presented as distinctive finishes on one real working instrument. They share typography, materials and interaction language, while serving different reading rhythms.

## Reference principles

The [research report](design/2026-10-14-ux-pro/research.md) contains live captures, selected library screenshots, source links and rejected examples. This is our interpretation of the evidence, not a claim that a reference causes conversion uplift.

| Reference | Useful principle | IZZY translation |
| --- | --- | --- |
| [Teenage Engineering TP–7](https://teenage.engineering/products/tp-7) | The physical mechanism deserves a large, closely observed view | Show actual rotor/casing/index craft; explain what the wheel does through its relationship to script movement |
| [Analogue Pocket](https://www.analogue.co/pocket) | A recognizable object can carry a generous, quiet composition | Make the remote legible at large scale; let contrast and framing create presence |
| [Playdate](https://play.date/) | A signature control gets a dedicated explanation | Give phone-as-remote and wheel-as-control one clear visual demonstration |
| [Moots finishes](https://moots.com/pages/finishes) | A finish is judged on the complete product | Show enough of each remote to understand its material character; retain a large inspection state |
| [Affinity](https://www.affinity.studio/graphic-design-software) | Real software can carry the visual proof | Use actual IZZY surfaces and skins rather than invented dashboard screenshots |

Borrow principles, not third-party artwork, layouts, fonts, brand marks or promotional copy. IZZY's existing studies and [design playbook](REMOTE_DESIGN_PLAYBOOK.md) supply its identity. The new owner requirement for ambient motion takes precedence over the playbook's older idle-motion guidance; preserve its honest-state and fixed-versus-moving-layer principles.

## Main page composition

- One strong typographic statement, one concise explanation, one clear start action; PRO remains an inviting secondary route.
- Script input stays immediately available. Its calm, useful appearance is part of the design, not a box squeezed beneath a marketing hero.
- The two-screen demonstration has a clear reading screen and remote. Wheel movement relates to the script; labels attach to the correct object. Scale, overlap and whitespace explain their roles without decorative arrows everywhere.
- Start with a warm, restrained studio direction using existing IZZY surfaces. Explore an alternative with more editorial contrast before selecting the final composition. Dark/light treatment is a means, not the concept.
- Below the first screen, change rhythm deliberately: short mechanism explanation → practical Online/Offline confidence → a strong PRO/skin invitation. Avoid repeating identical card rows.
- On a narrow phone, keep message, start/input access and mode legible; compose the remote at a meaningful size. Do not force the entire desktop scene to shrink into the first viewport.

## PRO composition

- Open with one large real remote, a concise ownership statement and the $49→$29 lifetime offer. Let the skin create desire before a dense benefit explanation.
- Use an intentional sequence of full-object views, close material details and a controlled collection view. The skin library should feel curated rather than like a settings panel.
- Maintain coherent light direction and believable boundaries between shell, bearing, rotor and fixed transport key. A finish should remain distinctive with motion paused and its name hidden.
- Give the section sequence changes in scale and density: hero → material/skin close view → collection → useful saved-workflow proof → reassurance → final purchase.
- Keep typography and price hierarchy precise. The discount sits quietly beside the offer; it does not become the dominant visual object. Use actual feature availability and owned states.
- Motion is slow and continuous where decorative, responsive where functional. Keep skin transitions coherent, native scrolling intact, and the static/reduced-motion composition complete.
- Mobile has its own framing/crops, spacing and section pacing. Large visuals can crop deliberately, while names, actions and controls remain readable. Sticky purchase UI must not consume the scene.

## D0 deliverables before final layout implementation

1. Annotated reference selection with one adopt/reject note per example.
2. Two coherent page pairs: main first screen, PRO hero and material/collection sequence; desktop and mobile in each. Show real copy, actual skin artwork and the approved offer.
3. One selected, refined full-page direction for each page, with a shared type/grid/material system and all major states accounted for.
4. A small motion proof covering wheel/script linkage, gesture priority and a skin transition; show its paused and reduced-motion states.
5. Visual review with the owner, followed by an implementation comparison against the selected direction. Refine the built page where browser rendering exposes weaknesses.

## Design acceptance scorecard

Score each dimension 1–5: 1 = materially unresolved, 3 = competent but ordinary, 4 = strong and deliberate, 5 = exceptional. Use screenshots and actual interaction as evidence; the numbers organize critique and do not replace judgment. Target at least 4 on every dimension. Any accessibility, comprehension or usability defect blocks acceptance regardless of average score. Owner visual review is required; a model cannot self-certify extraordinary quality.

| Dimension | Observable review question |
| --- | --- |
| Identity | With the logo hidden, do wheel geometry, materials, typography and composition still feel like this product? |
| Main-page understanding | After a brief first-screen view, can a new reader identify the prompter, phone remote, and next action? |
| PRO desire | Do the actual skins invite inspection before reading a checklist? Does the finish remain distinctive in a still frame? |
| Composition | Is there a clear dominant object and deliberate balance of scale, density and negative space? |
| Typography | Are hierarchy, line breaks, alignment and reading sizes considered at every breakpoint? |
| Material craft | Do seams, shadows, highlights and moving/fixed parts describe a coherent object? |
| Page rhythm | Does each section earn its space and change the reading pace without repetitive containers? |
| Motion | Does movement explain or enrich the object, respect gesture priority, and remain smooth without scroll manipulation? |
| Mobile | Does the narrow layout look intentionally composed, with a large enough product and comfortable controls? |
| Finish | Are loading, unavailable, owned, focus, reduced-motion and first-load states equally considered? |

## Reasons to revise a design

Rework a direction if its impact depends on copied hardware photography, a giant headline alone, generic gradients, repeated feature cards, excess borders, fake technical labels, unreadable microtype, oversized empty screens, an obstructive discount badge, or a long animation before the product becomes usable. Do not retain a weak section merely because it has already been implemented.

Functional and visual acceptance are separate evidence. Both are required for the main and PRO pages.
